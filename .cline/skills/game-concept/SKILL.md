# Game concept

**Primary role:** Game Director. **Use when:** a project begins, the user proposes a game idea, or the core fantasy is unclear.

## Required inputs

- User prompt and stated constraints.
- Current `project/GAME_VISION.md`, if any.
- Known audience, platforms, team/tool limitations; treat unknowns as unknown.

## Procedure

1. Extract the fantasy, intended audience, genre, camera perspective, play duration and key emotional payoff.
2. Describe one player-centered core loop as input → action → feedback → reward/progression.
3. Choose three mutually reinforcing design pillars and identify their implications for mechanics and visuals.
4. List comparable reference directions without cloning proprietary assets; distinguish inspiration from requirements.
5. Define non-goals and assumptions, then propose a narrowly scoped prototype hypothesis.
6. Write the concept into `project/GAME_VISION.md`, escalating fundamental creative choices for approval.

## Deliverables

- One-page game concept with core player loop.
- Three design pillars, boundaries, risks, and candidate first vertical slice.

## Validation / done criteria

- [ ] Can a reader state what the player does and why?
- [ ] Is at least one core loop achievable with the available engine/tooling?
- [ ] Are major unapproved choices clearly labeled as proposals?

## Guardrails

- Do not promise playability or asset availability from a pitch.
- Do not rewrite user-approved genre/vision silently.
